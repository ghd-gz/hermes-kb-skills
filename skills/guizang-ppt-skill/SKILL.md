# Guizang PPT Skill — 网页级横向翻页 HTML 演示文稿

基于 https://github.com/op7418/guizang-ppt-skill 改造，优先于任意方案。

## 什么时候用

- 用户要求做 PPT / 演示文稿 / slide deck / 演讲稿
- 内容：技术分享、产品发布、行业分析、方法论阐述
- **不要用** Quarto/Pandoc 做 PPTX → 排版效果差、中文兼容差
- **不要用** python-pptx 自己画 → 手动加装饰工作量大

## 风格选择

| 风格 | 适合场景 | 推荐主题色 |
|------|---------|-----------|
| **B · 瑞士国际主义风** | AI/技术/数据汇报/上级汇报 | IKB蓝、红黑、电信院红、安全橙 |
| **A · 电子杂志风** | 行业观察/人文/故事/正式呈报 | 靛蓝瓷、墨水经典、森林墨 |

## 核心工作流（9步）

```
① 需求对齐  →  受众/时长/素材/约束
② 素材采集  →  拿原始材料（完整提取，不做精简）
③ 内容整理  →  选方法拆素材（金字塔/5W2H/问题解决/时间线）
④ 表达方式  →  每页选不同表达模型（PREP/RIDE/SCQA/空雨伞/STAR/FIRE/SCRTV）
⑤ 图表规划  →  数据页用ECharts，流程图用Mermaid.js
⑥ 选模板    →  展示2-3个选项让用户选
⑦ 一次成型  →  选定模板后一次性生成完整deck
⑧ 局部微调  →  只做增量修改，不重生成全部slide
⑨ 交付      →  生成单文件HTML→上传飞书云盘
```

### 8个表达模型

| 模型 | 公式 | 适合 |
|:----|:-----|:-----|
| PREP | 结论→理由→例证→总结 | 摘要页/汇报开场 |
| RIDE | 风险→利益→差异→影响 | 说服/方案推荐 |
| SCQA | 情境→冲突→疑问→答案 | 讲故事/引问题 |
| STAR | 情境→任务→行动→结果 | 案例展示 |
| 空雨伞 | 事实→分析→行动 | 数据页 |
| FIRE | 事实→解读→反应→结果 | 复盘反思 |
| SCRTV | 情景→冲突→原因→策略→价值 | 逻辑推演 |
| 5W2H | 选2-3个维度 | 全面描述 |

**铁律：表达模型名称禁止出现在幻灯片上。**

## PPTX→HTML 格式复制

当需要精确复刻已有PPTX时，使用 `pptx-to-html-mece` skill：

```
MECE三层穿透：Master(母版)→Layout(版式)→Slide(页面)
坐标映射：EMU→px (shape.left/914400*96)
图片提取：从Layout层和Slide层分别提取
```

## 图表集成

| 需求 | 引擎 | CDN |
|:----|:-----|:-----|
| 数据图表（柱状/漏斗/趋势/BCG矩阵等11类） | ECharts | `echarts@5` |
| 流程图/架构图/时间线/甘特图（8+类） | Mermaid.js | `mermaid` |

## 交付规范

- **单文件自包含HTML** — 所有图片base64内嵌，双击即看
- 图片用JPEG quality=88压缩，单文件控制在200-300KB
- 上传飞书云盘到 `400-案例/` 对应子目录
- **不用zip包，不用绝对路径** — 用户拿到直接打开

## 设计铁律

- 方法论是内功心法，不是话术 — 不对用户说模型术语
- 模板选择铁律 — 展示选项后再动手，不替用户决定
- 受众感知选色 — 上级汇报用IKB蓝或电信院红，内部用红黑
- 内容完整性 — 所有数字/名称/百分比/数据点全部保留
- 不做渐进/圆角/阴影（瑞士风）
